# 租客 H5“我的房间”页面测试

## 场景与前置条件

- 页面：租客 H5 `/tenant-h5/room`，使用租客账号访问。
- 有入住场景依赖本用例专属的租客、公寓、房间和在住租约；无入住场景使用没有租约的新租客。
- 页面数据来自 `GET /tenant-app/my/room` 和 `GET /tenant-app/my/room/history`。

## 用例矩阵

| ID | 名称 | 前置 | 操作步骤 | 预期 |
|---|---|---|---|---|
| TR-001 | 在住租客查看房间与租约详情 | 本用例专属租客有有效在住租约 | 登录；打开 `/room`；等待当前房间与历史租约接口 | 页面显示公寓/房间、楼层、户型、面积、地址、联系人、电话、入住日期、押金、月租；当前房间字段与 API 及测试准备数据一致 |
| TR-002 | 无房间记录时显示空状态 | 本用例专属租客没有当前租约和历史租约 | 登录；打开 `/room`；等待两项数据接口 | 当前房间接口 HTTP 200、业务码 500；历史接口 HTTP 200、业务码 200 且为空；页面显示“暂无房间信息” |

## 探索记录

- 用 headed Playwright CLI 登录临时租客，从首页“当前房间”卡点击进入 `/tenant-h5/room`。
- 在住页面显示公寓/房间、楼层、户型、面积、地址、联系人、联系电话，以及入住日期、押金和月租；真实数据分别与租客端当前房间接口返回和本轮临时数据一致。
- 使用第二个无当前/历史入住的临时租客打开 `/room`，页面显示“暂无房间信息”；`GET /tenant-app/my/room` 返回 HTTP 200、业务码 500、提示“当前没有在住记录”，history 接口 HTTP 200、业务码 200、列表为空。
- 快照：`tenant-room-login-snapshot.md`、`tenant-room-home-snapshot.md`、`tenant-room-active-snapshot.md`、`tenant-room-empty-snapshot.md`。页面字段采用 `.kv-row`/`.kv-label` 语义结构，无独立 testId；通过角色/名称优先策略选择登录字段与标题，字段用 label 过滤。
- 探索完成后，已退房并核验房间空置；临时房间、公寓及有/无入住两名临时租客均已清理。

## 验证结果

- “我的房间”定向回归 **2 passed（1.8s）**；由于测试扩展了首页共用数据 fixture，随后首页与房间页面组合回归 **4 passed（3.0s）**。
- 两条房间用例均生成截图、视频和 Trace；运行数据在 fixture teardown 中完成退房、房间空置核验和依赖清理。
- TR-001 的租客数据 fixture 复用 `tenant-home-data.fixture.ts`，并创建有唯一地址、联系人和房间/租约属性的动态业务数据；teardown 先退房核验房间空置再清理依赖。
- TR-002 仅创建独立租客账号，不创建入住数据；teardown 删除账号。
