# 租客 H5 首页测试

## 场景与前置条件

- 页面：租客 H5 首页 `http://localhost:3001/tenant-h5/home`。
- 每条用例创建独立临时租客账号；有房间场景额外创建临时公寓、房间和入住记录。测试结束先退房并核验房间空置，再清理依赖数据。
- 租客登录使用手机号和密码；首页当前房间数据来自 `GET /tenant-app/my/room`，页面同时加载租客工单、公告、账单和催租消息。
- 当前前端没有“全部已读”按钮；`POST /tenant-app/rent/messages/read-all` 只有 API 方法，故本组覆盖真实可见的未读提醒展示，不把不存在的页面操作写成 UI 用例。

## 用例矩阵

| ID | 名称 | 前置 | 操作步骤 | 预期 |
|---|---|---|---|---|
| TH-001 | 首页展示租客欢迎语与本人当前房间 | 独立临时租客有一条有效入住记录 | 登录租客 H5；等待首页数据请求 | 首页显示租客姓名、当前公寓与房间、户型/面积/楼层摘要及快捷入口；房间卡信息与 `GET /tenant-app/my/room` 返回一致 |
| TH-002 | 无当前入住时首页不显示房间卡 | 独立临时租客账号尚无入住记录 | 登录租客 H5；等待首页数据请求 | `GET /tenant-app/my/room` HTTP 200、业务码 500、提示当前没有在住记录；首页仍正常显示欢迎语和快捷入口，不显示“当前房间”卡片 |
| TH-003 | 首页提示有未读催租消息 | 独立临时租客有未缴账单；管理员对该账单发送催租提醒 | 登录后打开首页并读取催租消息和账单接口 | 首页“房租账单”入口显示提醒标记；消息接口返回与本次账单关联的未读消息；账单仍未缴 |

## 探索记录

- 使用 headed Playwright CLI 登录本轮临时租客后进入 `/tenant-h5/home`；欢迎标题为“你好，{租客姓名}”，底部有首页、工单、我的导航。
- 有有效入住记录时，首页显示“当前房间”卡片、公寓名与房间号，以及户型、面积、楼层摘要；页面还显示申请维修、我的工单、房租账单快捷入口。
- `GET /tenant-app/my/room` HTTP 200、业务码 200，返回房间与公寓信息；页面摘要与接口及本轮创建数据一致。
- 探索中先通过租客业务接口退房并核验房间状态为空置，再刷新同一租客首页：当前房间卡片消失，欢迎语和快捷入口仍显示。无入住时房间接口返回业务码 500、提示“当前没有在住记录”，页面仍可正常完成加载。
- 快照：`tenant-home-login-snapshot.md`、`tenant-home-active-room-snapshot.md`、`tenant-home-no-room-snapshot.md`。页面入口按钮使用精确可见文本；当前房间卡使用已有 `.apple-card` 文本结构，无独立 testId。
- 探索数据已退房并核验空置，临时房间、公寓和租客已清理。
- TH-003 使用专属入住自动生成的账单，由管理员对该账单调用提醒接口；租客首页重新加载后，`GET /tenant-app/rent/messages` 返回该账单的 `readFlag=0` 消息且 `unreadCount>0`，账单状态仍未缴，房租入口的 `.quick-badge` 可见。首页 badge 同时可由未缴账单数量触发，因此它不能单独区分“未缴账单数”和“未读催租数”；该用例用消息接口校验未读归属，用 UI 断言入口标记存在。

## 验证结果

- 租客首页 TH-001 至 TH-003 在联合定向回归中 **3 passed**；每条均生成截图、视频和 Trace。TH-003 新建的账单及催租消息没有删除接口，会在本地数据库保留业务历史；其租客和住房 fixture 已按清理规则退房、核验空置并清理可删除依赖。
- TH-001 fixture 独立创建临时租客、公寓、房间和入住；清理先退房并核验房间空置，再删除房间、公寓、租客。TH-002 只创建无入住租客账号并在结束时删除。
