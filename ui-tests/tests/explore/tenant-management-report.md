# 租客管理：用例矩阵与探索报告

## 输入与范围

- 起始 URL：`http://localhost:3000/tenants`。
- 前置条件：管理员登录态有效，使用已有的本机 storage state；不在报告、代码或日志中记录登录凭据。
- 页面范围：租客列表、搜索/重置、新增、编辑、表单必填校验、删除。
- 本组不执行设置/重置密码操作；密码重置会在界面显示默认密码，避免密码进入截图、视频和 Trace。
- 个人资料使用动态虚构测试数据，手机号以 `199` 开头，证件号使用 `TEST` 前缀；用例创建的数据由自身删除。
- 预期来源：前端 `TenantManagement` 表单与列表实现、租客接口定义，以及现有接口测试对手机号/身份证脱敏的约定。尚待页面探索和运行验证的断言会在后续章节注明。

## 探索记录

- 使用 `npx playwright-cli open http://localhost:3000/tenants --headed`；首次访问重定向到登录页，随后加载本机已有的 `tests/explore/apartment-list-auth.json` 并回到 `/tenants`。
- 页面结构快照：`tenant-management-snapshot.md`。观察到姓名、性别、手机号、身份证搜索项；新增/刷新按钮；表格列为姓名、性别、手机号、身份证、更新时间、操作；行操作为编辑、设置密码、重置密码、删除。
- 列表中现有模拟记录显示手机号如 `199****5678`、身份证如 `TESTa1****f6a7`，与 API 测试中的脱敏约定一致；报告只记录格式示例，不记录完整个人资料。
- 新增表单快照：`tenant-management-create-snapshot.md`。字段为姓名、性别、手机号、身份证、备注；提交按钮“确定”。使用 `getByRole` 打开弹窗并操作，CLI 观察确认创建成功后列表刷新。
- 必填校验快照：`tenant-management-validation-snapshot.md`。空提交分别提示“请输入姓名”“请选择性别”“请输入手机号”“请输入身份证号”。
- 使用显式标记的虚构数据验证创建后脱敏和删除，探索记录已删除。未触发设置密码或重置密码操作。
- Locator 层级：新增/搜索/编辑/删除/提交按钮及姓名/备注/性别控件使用 role + 可访问名称；手机号和身份证输入在快照中没有可访问名称，测试退化到 `.ant-form-item` 限定下的 textbox。表格通过 role/columnheader/cell 定位。建议产品在租客管理页给关键表格、筛选框、手机号/身份证输入、操作按钮和弹窗按钮增加 `data-testid`。
- CLI 输出代码片段主要采用 `page.getByRole('button', { name: /新增租客/ })`、`dialog.getByRole('textbox', { name: '* 姓名' })`、`row.getByRole('button', { name: /删除/ })`。
- `TM-004` 首轮失败：名称正则 `/重\s*置/` 同时匹配页面查询“重置”和多条行内“重置密码”，触发 strict mode；属于自动化定位冲突。
- `TM-005` 首轮失败：编辑弹窗保持打开，姓名已填入新值、性别仍是“男”，未提交更新。Trace 指向点击 role combobox 超时。CLI 复现确认编辑态直接点击 combobox 输入控件无法稳定展开，而点击可见 `.ant-select-selector` 容器可显示“未知/男/女”三个选项；页面没有相应产品缺陷证据。
- 首次无头回归在受限沙箱中因 Chromium macOS 启动权限失败；授权本机环境重跑后进入页面，第一轮为 5 passed、2 failed。每条失败项已生成截图、video 和 Trace。
- 用户确认自动修复后，TM-004 筛选“重置”按钮改为可访问名称精确匹配 `重 置`，避免命中行内“重置密码”；TM-005 点击 `.ant-select-selector` 再选择可见性别 option。自动化仅修改 1 轮，未修改产品代码。
- 超时用例可能中断 finally 清理；已使用 CLI 对唯一失败记录执行查询并删除，列表恢复原先 2 条模拟租客记录。随后用于验证下拉的另一条虚构临时记录也已清理。
