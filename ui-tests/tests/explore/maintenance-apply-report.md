# 维修工单申请：测试矩阵与探索报告

## 输入与范围

- 起始 URL：`http://localhost:3000/maintenance-order/apply`。
- 前置条件：管理员登录态有效，具备维修工单申请权限。
- 当前本地测试数据没有确认中的在住房客人；后端创建工单要求所选租客存在有效入住记录。因此本组不提交真实创建请求，不产生新工单。
- 范围为页面列表、申请表单打开与关闭、必填校验、紧急程度选项、刷新接口请求。
- 预期依据：前端 `MaintenanceOrder/Apply.tsx` 表单和表格定义；后端 `MaintenanceOrderController.create` 的必填与入住前置条件。

## 探索记录与执行结果

- headed Playwright CLI 快照：`maintenance-apply-snapshot.md`、`maintenance-apply-form-snapshot.md`、`maintenance-apply-validation-snapshot.md`、`maintenance-apply-urgency-snapshot.md`。
- 页面实际显示 9 个表格列头：房间、租客、标题、描述、紧急程度、状态、处理备注、申请时间、操作；列表当前为空。
- 表单实际展示租客选择、工单标题、问题描述、紧急程度和现场照片上传控件。管理员必填项为租客、标题、紧急程度；留空提交后显示“请选择租客 / 请输入工单标题 / 请选择紧急程度”，未发出 `POST /maintenance-order/create`。
- 紧急程度下拉值为“普通、紧急、非常紧急”。列表刷新请求为 `GET /maintenance-order/apply/list`，定向回归中 HTTP 200。
- 新增页面对象 `pages/maintenance-apply.page.ts` 和测试 `tests/test_maintenance_apply.spec.ts`，覆盖矩阵 MA-001 至 MA-006。首次运行发现测试定位问题，经修正后最终 **6 passed（4.9s）**；每条用例启用截图、视频和 Trace。
- 测试不提交有效工单：当前没有确认可选的在住房客人，避免产生持久业务数据。未操作工单取消或维修状态流转。
