# 公寓列表管理：测试设计与探索报告

## 输入与范围

- 用例来源：项目 Skill `playwright-explore-to-test/examples/case-apartment-list.md`
- 起始 URL：`http://localhost:3000/apartment/list`
- 前置条件：管理员已登录；登录态使用浏览器 storage state，不在测试代码中硬编码凭据。
- 页面控件、表单字段、交互和定位方式已通过 Playwright CLI 实际观察；下面将观察事实与尚未验证的预期分开记录。
- 数据原则：新增、搜索、刷新、编辑、删除场景各自创建唯一测试公寓；每条用例独立运行，并清理自己创建的数据。禁止依赖已有公寓或分页位置。

## 探索记录

- 请求 `/apartment/list` 后实际跳转到 `http://localhost:3000/login`；页面标题为“智能公寓系统”。说明探索列表前必须先取得管理员登录态。
- 登录页可访问元素：标题“用户登录”；文本框“用户名”“密码”“验证码”；按钮“login 登录”；验证码图片“验证码”；图片内有一个可访问名称为 `reload` 的刷新按钮。
- 用户确认本地项目的演示验证码绕过值为 `2998`。使用该值和本地演示管理员账号完成 CLI 登录，并将登录状态保存在被 Git 忽略的 `tests/explore/apartment-list-auth.json`；测试代码不包含账号、密码或验证码。
- 已使用 CLI accessibility snapshot 观察登录页；`getByRole` + 可访问名称可定位三个文本框和登录按钮（优先级 2）。
- 控制台观察到 3 条错误，其中含 SVG `rect` 的 `rx` 属性值不符合浏览器预期，以及 favicon 404；暂未判断是否影响业务。
- 列表页面观察到名称、地址、联系人、电话四个搜索条件；搜索、重置、新增公寓、刷新按钮；表格表头为名称、地址、联系人、联系电话、操作。
- 新增和编辑表单字段通过项目级 `data-testid` 稳定定位；新增按钮、刷新按钮、编辑/删除行按钮和弹框确定/取消也有对应的 `data-testid`。
- 新增唯一公寓后，列表展示名称、地址、联系人和脱敏电话；删除会弹出“确认删除该公寓？”对话框。已删除探索临时数据，列表恢复到原来的 4 条。编辑表单仅打开观察后取消，未改动已有数据。
- 搜索、重置、编辑和刷新流程已写入 Playwright Test，仍需以自动化回归结果确认断言和清理逻辑。

## 断言与数据清理风险

- 页面加载断言以实际可访问名称和页面结构为准，探索后再落为稳定 locator。
- 所有写操作使用动态唯一数据；编辑/搜索/刷新用例须删除自己创建的数据。若页面不支持可靠删除，需要在报告里记录清理替代方案，不复用共享种子数据。
- 登录边界及列表用例将由 Playwright Test 回归验证；登录态文件仅用于本机运行，不提交到版本库。

- 已实现 AUTH-001、AL-001 至 AL-007，共 8 条测试；完整运行结果为 8 passed（14.2s）。
- 覆盖管理员未登录访问、列表展示、名称搜索、重置、新增、刷新后查询、编辑地址和删除确认。
- Playwright Test 使用系统 Chrome 无头执行；项目配置启用视频、Trace 与失败截图，HTML 报告由 `playwright-report/` 生成。

- 可访问名称优先用于页面语义断言；按钮和表单控件使用页面实际提供的 `data-testid`。测试不依赖已有公寓名称，也不删除共享种子数据。
