## 从测试入口理解分工

| 位置 | 职责 | 不负责什么 |
|---|---|---|
| apis/ | HTTP 方法、路径和参数，返回原始 Response | 不自动认定业务成功 |
| core/assertions.py | HTTP/业务码和 data=true 的公共响应检查 | 不替代金额、状态、归属或权限断言 |
| helpers/accounts.py | with 管理临时账号创建及 finally 删除 | 不合并 A/B 的账号数据或会话 |
| helpers/rent.py | 发起 MOCK 支付、确认、已缴详情/列表及原结果保持的公共业务步骤 | 不绕过真实接口、不改数据库状态 |
| helpers/maintenance.py | 工单 ID/租客/房间/状态、处理人与指派人的公共断言 | 不预设每个场景的状态或赢家 |
| conftest.py | 组合客户端、身份、前置与清理；新 paid_tenant_bill 提供已缴账单上下文 | 不决定测试想验证什么异常行为 |
| tests/ | 描述场景、调用接口/步骤、给出明确预期 | 不反复复制相同前置和响应模板 |

## 公共响应检查

原先 HTTP 断言、JSON 解析和业务码断言合并为：

```python
body = assert_response(response)  # 默认 HTTP 200、业务码 200
body = assert_response(response, code=500)
body = assert_response(response, http_status=400, code=400)
```

错误场景仍在调用处明确写错误码和 message，未改成“只要响应就算通过”。assert_true_response 另外要求 data is True。

bill = tenant_lease_bill
