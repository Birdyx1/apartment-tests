## D01：可选邮箱/手机号缺失触发唯一索引异常

- 触发：管理员 POST /system/user，仅传唯一 username、password、status=1、roleIds=[维修工角色 ID]。
- 实际：HTTP 500，创建账号的 fixture 失败，登录测试体未执行。
- 后端日志：Duplicate entry '' for key 'sys_user.uk_email'。
- 数据库核对：sys_user.email、phone 均不允许 NULL，默认空字符串，分别存在 uk_email、uk_phone 唯一索引。
- 源码：CreateUserRequest 的 email/phone 未标记必填；创建服务未对缺失值作与唯一约束一致的处理。省略字段后默认空字符串与已有记录冲突；仅补邮箱仍存在手机号同类风险。
- 当前测试数据调整：生成唯一邮箱（example.com 测试地址）与 11 位模拟手机号，使正常账号场景具备合法且可区分的数据。此调整不代表后端缺陷已修复。
- 2026-10-25 已检查学员 worker_payload，唯一邮箱和模拟手机号已补齐；删除权限修复后，完整维修工登录及清理用例已通过。D01 的后端空值处理缺陷仍保留。
- 后端修复建议：明确字段是否必填；若可选，统一数据库空值及唯一性策略并增加接口回归；重复或不合法输入应有明确错误结果，避免暴露数据库异常为 HTTP 500。此空值处理缺陷的后端与表结构尚未修改。

## D02：删除系统用户的权限编码与初始化数据不一致

- 创建使用唯一邮箱/手机号后成功，维修工登录也成功；用同一管理员会话 DELETE /system/user/{本次用户ID} 返回 HTTP 403/code 403。
- 实际权限配置：sys_menu 的用户删除权限编码为 system:user:remove，状态启用；docs/init.sql 同样使用该编码。
- 复现时，后端 SysUserController 的单个删除与批量删除注解要求 system:user:delete，与初始化配置不一致。
- 影响：正常创建账号后，created_worker 的删除后置无法完成；仅修正创建数据仍不能让用例完整通过。
- 修复建议：将后端、初始化配置及前端使用的权限编码统一，保留正式的鉴权检查；修正后重新部署并验证管理员删除成功、无对应权限的角色被拒绝。
- 2026-10-25 已将 SysUserController 单个与批量删除的鉴权编码统一为初始化配置已有的 system:user:remove，保留权限校验；本地源码已编译打包并构建为 raina-backend:local-user-permission-fix，仅更新 backend 服务，D02 通过回归并关闭。
- 本轮未增加管理员权限、未跳过鉴权、未将测试预期放宽为 403，也未为 fixture 加数据库删除兜底。
