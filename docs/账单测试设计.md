# 租客账单与本地模拟支付测试设计

## 范围与接口

本阶段覆盖入住自动出账、本人账单列表/详情、金额与日期、ALIPAY 渠道 MOCK 支付、重复支付拒绝、重复确认幂等、无效渠道和跨租客权限。不覆盖真实支付渠道、回调验签、并发支付或后台支付单数量审计。

| 接口 | 请求 | 关键语义 |
|---|---|---|
| GET /tenant-app/rent/bills | 可选 status | 从登录令牌取得租客身份，data 是列表 |
| GET /tenant-app/rent/bills/{bill_id} | 无请求体 | 检查账单归属 |
| POST /tenant-app/rent/bills/{bill_id}/pay | JSON channel | 发起支付，取得 paymentId，尚未代表账单已缴 |
| POST /tenant-app/rent/payments/{payment_id}/mock-confirm | 无请求体 | 本人模拟支付单确认，成功后账单状态 1 |

## 用例矩阵

| 场景 | 分层 | 执行数 | 验证重点 |
|---|---|---:|---|
| 入住出账与本人查询 | P0 | 1 | leaseId 唯一、本人/房间关联、Decimal 金额、月份、应缴日期、状态及详情一致 |
| 模拟支付成功 | P0 | 1 | mode=MOCK、支付单 ID、确认成功、已缴状态/时间/渠道/流水及已缴列表 |
| 已缴账单再次 pay | P1 | 1 | HTTP 200/业务码 500、账单已缴、无返回支付单，原支付信息不变 |
| 同一支付单重复确认 | P1 | 1 | 再次成功、原状态/金额/时间/流水不变 |
| 渠道缺失/null/空串/空白 | P1 | 4 | HTTP 400/业务码 400，渠道必填，原账单不变 |
| 不支持的渠道 BANK | P1 | 1 | HTTP 200/业务码 500，不支持的支付渠道，原账单不变 |

| B 确认 A 的模拟支付单 | P0 | 1 | 先存在真实 MOCK 支付单；B 被拒绝，A 账单未缴，随后 A 可正常确认 |
| 合计 | P0 5 / P1 7 | 12 | 当前账单模块全部通过 |

## fixture 与数据生命周期

- 原有 created_lease 准备新租客、新房间和入住；月租金大于 0 时后端为入住月份出账。
- tenant_lease_bill 查询并核对本次租约唯一账单，提供支付前快照；退房由其依赖的 created_lease 负责。
- created_second_tenant 创建 B 并负责删除；second_tenant_rent_api 使用独立 requests.Session 登录 B，退出时关闭会话。A/B 不共享令牌，也不重新登录管理员。
- B 无须入住便可测试账单归属，A 的账单和支付单均由本次测试实际产生，不使用随机不存在的 ID 替代越权场景。
- 支付及账单历史按业务保留，基础资料通过原 fixture 清理；不全表删除，不清空数据库。

## 关键设计与限制

1. 金额使用 Decimal(str(value)) 对比；当前月租金输入是 1500。日期预期来自本次入住月份及 rentDueDay=1，后端已过期账单直接为状态 2，不能把新账单固定当作状态 0。缴租日大于 28 的归一化边界暂未覆盖。
2. 发起支付使用账单 ID，模拟确认使用返回的支付单 ID；每次首次发起支付都断言 MOCK，测试不打开 payUrl。
3. 幂等场景在两次确认间等待 1.1 秒，确保接口秒级 paidTime 若被重写能被发现。
4. 错误响应之外重新查询 A 的账单，比较身份关联、状态、日期、金额和支付字段。未用直接数据库查询证明不存在额外支付行，不能将“未返回支付单”等同于“数据库支付单数量不变”。
5. B 是未入住的新租客，列表隔离检查确认排除目标 A 账单；B 列表为空时，所有行归属断言没有正向数据，不代表多租客混合数据矩阵已完整覆盖。
